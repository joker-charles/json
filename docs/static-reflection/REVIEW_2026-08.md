# 静态反射重写代码审查报告（2026-08）

> **范围**：`feature/static-reflection` 分支相对 `develop`（cdf52ae9）**未合入上游**的
> 全部改动，重点是与"用静态反射重写 json"相关的两部分：
> `include/nlohmann/reflection_to_json.hpp`（refl2 codec：M5 注解序列化 / M6 枚举 /
> M7 variant）与 `include/nlohmann/reflection_json.hpp`（rjson：私有 `json_value`
> 反射 + tagged-union API + 五种二进制格式读写），以及主库接线
> （`detail/conversions/{to,from}_json.hpp`、`detail/concepts/concepts.hpp`、
> `detail/input/{lexer,binary_reader}.hpp`、`single_include/nlohmann/json.hpp`）。
>
> **方法**：只读审阅 + 实证验证。关键手段是把上游**整套** doctest 源码（81 个 TU）
> 在 `-DJSON_USE_REFLECTION` 下做 `-fsyntax-only` 全量扫描，并用 ASan/UBSan、
> 跨标准差分（C++11/14/17/20/23/26）与最小复现逐条确认。
>
> **结论**：审查共确认 20 项缺陷（3 项致命、9 项重要、8 项次要/文档）。**本次已修复
> 16 项并逐条加入回归测试**，余下 4 项列为待办（见 §4）。核心事实：分支此前只在
> **1 个 TU** 里开启 `JSON_USE_REFLECTION`，因此"主库测试套件全绿"完全无法覆盖反射
> 路径——开启 gate 后上游自有测试有 **4 个 TU 直接编译失败**。

## 1. 最高优先级发现（已修复）

### R1 开启 gate 后上游自有测试 4 个 TU 编译失败（致命）

全量扫描命令：

```sh
for f in tests/src/unit-*.cpp; do
  g++-16 -std=c++26 -freflection -fsyntax-only \
    -Iinclude -Ibuild/include -Itests/thirdparty/doctest \
    -Itests/thirdparty/fifo_map -Itests/src \
    -DDOCTEST_CONFIG_SUPER_FAST_ASSERTS -DJSON_TEST_KEEP_MACROS=1 \
    -DJSON_TEST_USING_MULTIPLE_HEADERS=1 -DJSON_USE_REFLECTION "$f" || echo "FAIL $f"
done
```

| TU | 修复前 | 根因 | 修复 |
|---|---|---|---|
| `unit-udt.cpp` | `std::meta::exception: reflection does not represent an enumerable enumeration type` | `udt::book_id` 是不透明枚举（`enum class book_id : std::uint64_t;`）；M6 的 `serialize_enum`/`deserialize_enum` 无条件调 `enumerators_of(^^E)`，在不完整枚举上是**硬错误** | `enum_is_enumerable()`（`std::meta::is_enumerable_type`）守卫，不完整枚举回落整数路径 |
| `unit-noexcept.cpp:45,51` | `static assertion failed` | C++26 枚举 `to_json` 丢了 `noexcept` | 恢复条件 `noexcept(!annotated)`：未注解枚举 `noexcept(true)`（与上游一致），注解枚举不 noexcept（与它替代的宏一致，因为字符串路径会分配） |
| `unit-disabled_exceptions.cpp`、`unit-regression2.cpp` | `satisfaction of atomic constraint 'from_json_eligible<B,T>::value' depends on itself` | "非循环 ADL 探针"仍会经 `nlohmann::to_json/from_json` **CPO 对象**（`basic_json` 的关联命名空间）回到 catch-all 约束；`&&` 短路只能阻止**求值**，不能阻止**模板实例化** | 探针改为**惰性实例化**（`no_user_to_json_lazy<B,T,structural>` 特化），非候选类型根本不实例化探针 |
| `unit-regression2.cpp:569` | `static_assert(!is_constructible<json, variant>) failed` | M7 把**顶层** `std::variant` 加入 catch-all 白名单，直接违反上游 issue #1292 不变量 | 顶层 variant 改由 `JSON_USE_REFLECTION_VARIANT` 单独 gate（默认关闭）；struct 成员里的 variant 不受影响 |

### R2 畸形输入触发 `std::abort()`（致命）

`deserialize_one_impl` 定长容器分支对 `std::array<int,3>` 收到 `{"arr":[1,2]}` 时
`fprintf` + `std::abort()`（实测 `exit 134 / SIGABRT`），而上游抛
`out_of_range.401`；过长数组上游是忽略多余元素，此处一并 abort。
**修复**：改为 `j.at(i)` 索引赋值，与上游 `from_json_array_impl<std::array<T,N>>`
逐字一致（短数组抛 401、长数组忽略）。

### R3 `rbegin()/rend()` 对标量值返回悬垂引用（致命）

`reflection_iterator::operator*` 对标量/字符串/二进制把值物化到迭代器自有的
`mutable json m_scratch`，而 `std::reverse_iterator::operator*` 是 `const`、必须复制
迭代器（`stl_iterator.h` 的 `__tmp`），返回的引用指向已销毁的局部。
**实测**（ASan）：`*refl.rbegin()` → `stack-use-after-return`，帧内 `__tmp`。
**修复**：scratch 改为 `std::shared_ptr<json>`（副本共享，引用在临时迭代器销毁后仍有效）。

### R4 反射序列化器输出与上游不一致（致命，字节级）

| 项 | 修复前 | 上游 | 修复 |
|---|---|---|---|
| 浮点格式 | `std::to_chars`（Ryu），1.12% 的 double 与上游不同，且会对浮点值输出**裸整数 token**（`1.2345678901234568e+17` → `123456789012345680`，重新解析成 `number_unsigned`） | `detail::to_chars` + `format_buffer` 阈值 + `.0` 保证 | 委托给库自身的 `json(double).dump()` |
| UTF-8 转义 | 按**字节**转 `\u00XX`（`"é"` → `\u00c3\u00a9`），无代理对、无 UTF-8 校验 | 按**码点**转义 + 代理对 + `error_handler_t`（`type_error.316`） | 委托给库自身的 `json(string).dump()`（保留内部片段） |
| 浮点 UB | `f == static_cast<long long>(f) && abs(f) < 1e17`：转换先于范围检查（UBSan：`1e+300 is outside the range...`） | — | 调换顺序 |
| CBOR NaN/±inf | 写成 float32/64（`fa7fc00000`） | 规范半精度（`f97e00`/`f97c00`/`f9fc00`） | 补非有限分支 |
| UBJSON 浮点码表 | `ubjson_code<number_float> = 'd'`（与上游 `'D'` 不符，且该表未被使用） | `'D'` | 待办（表未接线，见 §4） |
| BSON 键含 U+0000 | 静默写出被截断的 cstr | `out_of_range.409` | 抛 `out_of_range` |
| BSON 重复键 | `emplace`（**first-wins**） | last-wins | `insert_or_assign` |

### R5 UBJSON 读取器读不了库自己的输出（致命）

`parse_typed` 没有 `'['`/`'{'` 分支，而 `ubjson_prefix` 对数组/对象返回 `'['`/`'{'`，
因此 `to_ubjson(v, use_count=true, use_type=true)` 生成的 `$[`/`${` 被读取器拒绝
（`invalid optimized element type`）。**实测**：`[[1,2],[3,4]]` 的库输出
`5b245b2369...` 库可读、反射读取器失败。**修复**：补 `case '['`/`case '{'` 分发。

### R6 不可信输入的内存放大（致命）

四个 `reserve()` 直接用攻击者声明的元素数：9 字节 CBOR 头声明 2³² 元素会 reserve
≈69 GB，`SIZE_MAX` 附近抛 `std::length_error`/`std::bad_alloc` 逃出 `bool` API。
**修复**：`reserve(min(count, 剩余输入字节数))`（每个元素至少 1 字节），并把
strict end-of-input 检查补齐（CBOR/MsgPack/UBJSON/BSON 均接受尾随垃圾字节）。

## 2. 重要发现（已修复）

| # | 位置 | 问题 | 修复 |
|---|---|---|---|
| R7 | `lexer.hpp` C++11/14 回退 | 丢掉了上游的 `value == x` 往返检查，自定义窄整数类型（`basic_json<...,int32_t,uint32_t,double>`）越界 token 被**静默截断**：`parse("4294967296")` 由 `4294967296.0` 变 `0`，`parse("-2147483649")` 变 `2147483647` | 恢复往返检查（`narrowed != x` 即失败，回落浮点路径） |
| R8 | `lexer.hpp` include 顺序 | `#ifdef JSON_HAS_CPP_17` 出现在定义该宏的 `macro_scope.hpp` 之前 → 单独包含 `lexer.hpp` 在 C++17+ 下编译失败（`'from_chars' is not a member of 'std'`） | 把 `macro_scope.hpp` 提到 `#ifdef` 之前；顺手补 `<cstdint>`、删除失效的 `<cstdio>` 注释 |
| R9 | `reflection_to_json.hpp` 标识符路径 | 64 字符成员标识符填满 `char[64]` 且无 NUL，`std::string(key.data())` 越界读（实测键里混入了相邻堆数据） | consteval 长度检查 → 可读编译错误；新增负向编译用例 `cf_long_identifier.cpp` |
| R10 | `reflection_json.hpp` 异常安全 | `assign_from`/`operator[]` 先发布 `m_type` 再 `new`，且 `destroy()` 不清 `m_value` → 分配失败时析构 `delete` 垃圾指针 | 先构造后发布；`destroy()` 清零 union |
| R11 | `reflection_json.hpp` 断言 | 手写 `slot_index` 与反射生成的 `kMemberIds` 之间**没有** static_assert（`FEASIBILITY.md §4.5` 声称有）；`:2298` 是恒真断言 `x == x` | 新增 8 条槽位↔成员名绑定断言 + `kStorage.size()==kMemberCount`；恒真断言改为「null/discarded 无槽位」 |
| R12 | `reflection_json.hpp` `erase(iterator)` | 缺上游的 `is_begin()` 守卫，`erase(end())` 静默销毁值 | 补 `iterator out of range` 检查 |
| R13 | `reflection_to_json.hpp` 对象键 | `key_from_string` 忽略 `from_chars` 错误，`{"abc":1}` 进 `map<int,…>` 静默变成键 `0`（键碰撞/数据丢失） | 抛 `type_error.302` |
| R14 | 文档 | `json_has_cpp_26_reflection.md` 称"手工定义无效"（实际会导致编译失败）；feature 页称 variant 开箱即用、未记录枚举与宏的语义差异 | 三处文档更新（含新增的 `JSON_USE_REFLECTION_VARIANT` 说明） |

## 4. 未修复（待办）与理由

| # | 项 | 影响 | 建议 |
|---|---|---|---|
| O1 | `concepts::array_like` 与 `is_compatible_array_type` 对 C++20 视图（`filter_view`/`iota_view`）判定不同（trait=1 / concept=0），且用 `remove_cvref_t` 与 trait 的 cv 敏感写法不同 | 当前**不可观测**（数组重载另有 `not_range_view` 排除），一旦去掉该排除即成活 bug | 让 concept 逐字镜像 trait：用 `T` 而非 `remove_cvref_t<T>`；视图分支按 `type_traits.hpp:520-544` 补上 |
| O2 | BSON `to_bson_length` 直接 `static_cast<int32_t>`，超过 INT32_MAX 时写出负长度（上游抛 `out_of_range.412`） | 仅 >2 GiB 文档 | 补范围检查 |
| O3 | UBJSON 码表 `'d'` 应为 `'D'`，且 `kMsgpackCodes`/`kUbjsonCodes` 实际未被 writer 使用（只有 `kBsonCodes` 在用） | 表与实现不一致；若按注释"接线"会把每个 double 写成 `'d'` | 要么接线、要么删除；同时修正 `'d'` |
| O4 | 读取器 F5–F8：CBOR tag `0xD5/0xD6/0xD7` 误接受；UBJSON `{$N#…}` 误接受；BJData 对象 ndarray 前导误接受；空 ndarray 维度向量误判 | 接受上游拒绝的输入（非静默错值） | 逐条对齐上游守卫 |
| O5 | 递归深度无上限（与上游一致，BSON 深度 2 万即段错误） | 与上游行为相同，非本分支引入 | 若加固需两侧一起做 |
| O6 | msgpack/UBJSON 长度阶梯在 >4 GiB 容器上写截断的 32 位长度（上游不写前缀） | 理论路径 | 对齐上游 |

> 说明：O1–O6 均**不影响**本次修复的正确性，但都不满足"与上游字节/行为一致"的
> 合入标准，建议在 PR 前处理。
